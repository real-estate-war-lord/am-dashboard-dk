# P3 — Shared IndicatorPicker, PeriodControl and chips

## Scope (spec §4.2, §4.3, §2.4 number rules for labels)
1. Build ONE `IndicatorPicker` (button + popover: search, grouped rows in `GROUP_ORDER`, unit, `↓ lower is
   better`, availability tag `2016–` / `snapshot` / `muni`, Outlook group pill `Projection`, Climate group pill
   `Horizon`; keyboard: ↑/↓/Enter/Esc; `role=listbox` + `aria-activedescendant`; `aria-expanded` on the button).
   Plus the chips row (`QUICK_KEYS` ∩ available at the level; active chip filled). All `data-testid`s per §10.
2. Build ONE `PeriodControl` with modes year / horizon / projection (§4.3); switching family resets `y`/`hz`.
   Climate indicators use the horizon mode (reuse `CLIMATE_CORE` hz helpers); Outlook shows the static
   projection badge.
3. Replace the old `<select id="indsel">` + year select + chips on **Map**, **Data › Areas** and **Charts**
   with the shared components (area page and test property adopt them in P5/P6 — leave their old selectors
   working until then). Selecting updates only dependent parts where the view already supports it; a full
   render is acceptable on Map/Data/Charts if scroll position and map view are kept.
4. Data › Areas: active indicator column highlighted (`th[data-col=<key>].on`) and sorted by it (AC-D5).
5. Charts: Climate indicators plot horizons on the x-axis (Today/2070/2120) as bars per area (AC-C2);
   `data-testid=chart-svg`, `[data-series]` (AC-C1).

## ACs (phase P3)
AC-I1 (on the routes that exist and have adopted the picker: map, data/areas, charts), AC-I2, AC-I3, AC-I4,
AC-T1, AC-T2, AC-D5, AC-C1, AC-C2. AC-I5 is delivered in P5.
