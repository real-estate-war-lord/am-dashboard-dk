## 1. A pasted link on the Map stays on the Map
Today: typing/pasting a Google Maps link or `lat, lon` into the map search offers only one result,
`search-coord` → "Open as test property", which navigates away to `#property`. The owner wants to
**stay on the macro map first**: the pin lands on the map, the map pans to it (a sensible zoom, e.g. 13),
the radius rings are drawn (`TP.rad` default 1 km), and he can study the area at macro level before
opening the sheet.
- Selecting the coord row (or pressing Enter on a coord) sets the pin (`pin=`/`pl=` keys already exist in
  the map hash — reuse them) and does **not** change `S.view`.
- The map shows a small pin card near the toolbar/info strip (`data-testid=pin-card`): label, coordinates,
  area names (quarter › postal code › municipality), and two buttons: **`View test property ›`**
  (→ `#property?p=…`, `data-testid=pin-open`) and **`×` remove pin**. Keep the existing "Test-property
  radius" row in Layers ▾.
- The search dropdown row text becomes "Drop a pin here" (sub: coordinates). Keep `data-testid=search-coord`
  so AC-M3 still finds it, and update AC-M3 in `tests/ui_ac.py`: after clicking it, `location.hash`
  starts with `map` and contains `pin=`, `[data-testid=pin-card]` is visible, and clicking
  `[data-testid=pin-open]` lands on `#property?p=…`.
- The Test property page's own paste box keeps its current behaviour (replaces the pin, stays on the page).

## 2. Services on the Test property map
`TP_LAYERS` has Infra, Public buildings, Buildings — **no Services**. Add the Services layer (groceries,
food & drink, pharmacies, public-transport stops; OSM & Rejseplanen) to the test-property Layers ▾ with
the same category filters as on the macro map, drawn within the ring on the property mini-map with its
own legend card (per-map panes/renderers — `map._am`, never the macro map's). URL key: extend `lay=` on
the property route with `services` (+ the existing `srv=` filter keys). Default off. Add an AC
(`AC-TP7`): on `#property?p=55.69711,12.58399&lay=services`, `[data-layer=services]` is checked and
`[data-testid=legend-services]` is visible inside the mini-map; toggling it off removes the legend.

## 3. Every layer on the Test property map can be switched off — and the state sticks

## 4. The full indicator list on the Test property (incl. Climate)
When the pin falls in a Copenhagen quarter, the picker offers `IND_Q` (the quarter registry, ~31 keys)
and therefore no Climate group, no BBR Housing-stock (BBR) group for the municipality, etc. The owner
wants the **same choice as on an area page of the same place**: the pin's finest level's own indicators
first, then everything the municipality (and postal code) publishes under "From the municipality" /
"From the postal code" with the `muni` tag — exactly the inheritance rule the area page already uses
(§4.2 AC-I5, `inherits()`/`eVal()`). Climate must appear (municipality level; `surge_dw_pct` has its own
quarter/postal value) with the horizon PeriodControl, and selecting a Climate indicator on the property
page draws the storm-surge zones in the mini-map like on the area page. Check the existing
`read as quarter` pill: keep it if it switches the *entity level*, but the picker must list the inherited
groups regardless. AC (`AC-TP9`): on `#property?p=55.69711,12.58399` the picker popover contains a
`[data-group="Climate"]` header and ≥ 55 `[data-ind]` rows; `#property?p=55.69711,12.58399&ind=surge_dw_pct`
shows `period-hz`, `clim-bars` in the chart panel and `[data-testid=legend-zones]` in the mini-map.
