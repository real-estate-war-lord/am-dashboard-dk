## Scope (spec §4.9, ENG_BRIEF §3; owner wishes 1, 2, 4)
1. `src/export_core.js` (IIFE → `window.EXPORT_CORE`, pure, `node --test`ed): row builders for
   - **areas_long** — schema exactly as spec §4.9 (`level, code, name, parent_code, parent_name, region,
     population, indicator, label, unit, period, period_type, value, value_type, inherited_from, direction,
     source, table_id, source_url, as_of, fetched, licence`), municipalities + postal codes + quarters, with
     postal/quarter rows for municipality-level indicators as `value_type=inherited`;
   - **projects** (own schema, never in indicator columns), **national_series**, **sources** catalogue,
     **climate exposure** (dwellings in zone per level × horizon), **test property** (+ nearby file, §5.5′),

   - Source columns filled per ENG_BRIEF §3.2 (publisher map, `tables`, `src_page`, `proj`, `climate_src`, KK
     table id parsed from the `source` string with `https://api.statbank.dk/v1/s30/tableinfo/<id>`); no blank
     `source`/`as_of`; `table_id` = `n/a (register/curated)` where none exists.
   - **Unit fix**: `fmt: kdkk` indicators are stored in DKK — write the raw value with unit `DKK / yr`
     (lossless) and never label DKK values as kDKK (AC-X2 adapted: every row whose unit contains `kDKK` has
     |value| < 10 000).

2. **Export ▾ menu** (`export-btn`, `export-menu`, `[data-export=view|areas|projects|national|sources|
   climate|property]`) in the Data header, the test-property header and the sidebar footer (same menu). A small
   toast "areas_long_<date>.csv · N rows". Lazy files (public, schools, zones) are awaited before export.
3. Remove the old `exportAll` single-CSV path and its 4-line sidebar explanation; Data › Sources shows the
   same catalogue the export writes.
