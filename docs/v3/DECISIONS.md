# v3.0 — decisions taken during the unattended build

One line per decision, prefixed with the phase that took it. Written when the spec left a choice
open and nobody was awake to make it.

- P1: `dropMap()` also clears the macro map's draw caches (`LF.level/ctx/pubDrawn/srvDrawn/climDrawn/microMarks/tpMark`). They describe what is drawn on a map that no longer exists, and a stale `pubDrawn` would skip the first redraw after the map is rebuilt.
- P1: the per-map renderer set is `map._am = {base, srv, pub, clim}`, created lazily by `mapPanes(map)`. Lazily rather than at every `L.map()` call site, so a builder that is handed a map built elsewhere (`pubMarkers`, `pubClusterMarkers`) can still ask for the panes it needs and never reaches for another map's.
- P1: one shared `LF.initTimer` for every map init, not one per view. Only one view is on screen at a time, so a shared timer is what "the last render wins" actually means.
- P1: `L.Map.prototype._getMapPanePos` returns `L.point(0, 0)` when the pane is gone, rather than `undefined`. Callers do arithmetic on the result; a zero offset is the only answer that cannot throw one frame later.
- P1: the alias table maps `#compare?a=…&b=…` to the **a** side's area page, and to `#map` when `a` is missing or unparsable — owner amendment A1 says Compare is deleted but not which side survives; the first one named is the one the reader chose first.
- P1: `#market?src=1` (and the existing `#sources` alias) land on `data/sources`, plain `#market` on `data/national`. The v2.6 `src=1` was "market with the sources panel open", which is exactly the new Sources tab.
- P1: `route_core.buildHash()` leaves `,` `:` `;` `/` unescaped. They are legal in a fragment and are what makes `property?p=55.6545,12.539:Test` readable; AC-TP1 checks that literal spelling.
- P1: the property codec (`propParse`/`propSerialise`) is list-capable (`;` separated) although v3.0 shows one pin — owner amendment A2 asks for the URL codec to stay list-capable for the LATER portfolio.
- P1: `tests/ui_smoke.py` waits for a landmark with Playwright `state="attached"`, not the default `"visible"`. Leaflet panes have no size of their own, so the visible wait always timed out — 15 s × 3 viewports per run, for nothing.
- P1: `OVERFLOW_FATAL = False` in `tests/ui_smoke.py`. Phone-width overflow is a v2.6 defect on all 28 routes; it is reported as a note until P8 rebuilds the responsive shell.
- P1: design tokens go in a third `:root` block at the end of `style.css` rather than into the two existing ones. Nothing above is edited, and the cascade puts the v3 values last.
- P2: `ROUTE_V3` is gone rather than set to `true`. With the flag on there is no second code path to keep alive, and a dead branch behind a `false` would only have to be deleted later; `parseHash()` now calls `RC.toInternal()` unconditionally, the way it already calls `CC.hzSerialise()`.
- P2: `route_core.toV3()` gained `opts.keepClimateFlag`, and app.js passes it. The alias table can already turn `climate=1` into a Climate indicator, but the overlay button it belongs to is still the working control — converting it now would silently delete the overlay two phases before the Climate phase rebuilds it. The Climate phase drops the option and the option's test.
- P2: `parseHash()` ends with a canonical `replaceState` of `hashFor()`, not only of the alias rewrite. The URL is the state: after any load the address bar shows exactly what the app would serialise, so an old link redirects once, a bare `#data` becomes `#data/areas/kommune`, and AC-U1's round trip is true by construction rather than by luck. `replaceState` never fires `hashchange`, so this cannot loop.
- P2: the Data tabs are one bar rendered by `dataTabs()` at the top of `vTable`/`vPipeline`/`vMarket`, not a new view wrapping the three. The internal view ids (`table`, `pipeline`, `market`) and their state objects are untouched — only the hash spelling, the labels and the breadcrumb moved, which is what R3 in the engineering brief asks for.
- P2: `#market?src=1` renders the Sources tab *instead of* the National series page, not as a fold under it. The v2.6 `src=1` meant "market with the sources accordion open", which is exactly the new tab, and a tab that also renders the previous tab above it is not a tab.
- P2: Data › Sources drops the `wraphead` table class. That class exists for the very wide Areas table (`white-space:nowrap` on the row head, `max-width:104px` + ellipsis on every `.dim` cell) and it clipped the catalogue names and the licences. The sources table uses `table-layout:fixed` with per-column widths instead.
- P2: the "Used for" column joins indicators to the catalogue through their `tables` list; the eleven register/curated sources (BBR, public buildings, infra, schools, boligstat, LBF, the two forecasts, net dwellings, the KK safety survey, the climate index) carry no table id, so what they feed is named from the repo's own docs in `SRC_USED_EXTRA` rather than left blank.
- P2: `enableSort()` skips `th[data-nosort]`, used for the sparkline and the ↗ columns. Sorting a column of sparklines or of identical link glyphs re-orders the table by nothing.
- P2: the old `#compare` link lands on the **a** side's area page (decided in P1, unchanged here). `scripts/ui_check.py` still asserts the compare view's climate rows and will fail its compare group until someone updates it — it is outside this run's allowed files and is not part of `./overnight.sh gate`.
- P3: the picker's pure logic goes into a new `src/picker_core.js` (IIFE → `window.PICKER_CORE`, wired into `src/index.html` and `build_dashboard.py` as `{{PICKER_JS}}`), like `climate_core.js`/`route_core.js`. `GROUP_ORDER` moved there, so there is one definition of the group order for the popover, Charts and anything later; app.js reads it as `const GROUP_ORDER = PC.GROUP_ORDER`.
- P3: the picker writes to one of two targets, named by `data-target` on the component (`ind` = the global `MK.ind`, `chind` = the chart generator's `CH.ind`). Charts needed its own indicator state long before v3 and still does; a second picker implementation for it would have been the thing the spec's "one picker" rule exists to prevent.
- P3: rows and chips both use `data-ind=<key>` (spec §10) and the old `data-indq` is gone. `tests/ui_ac.py`'s AC-U1 interaction moved from `[data-indq]` to `[data-testid=ind-chips] .chip` — the same click on the same control under its v3 name, and it now also fires on Charts, which had no chips before.
- P3: the popover is rendered with the view and hidden, not built on open. Opening toggles one class, so no re-render happens and the search box keeps focus (AC-I2); a pick re-renders and the fresh markup is closed again.
- P3: `yearSelect()` became an alias of `periodControl("ind")` rather than being left alongside it. The area page, the sheets and the test property still call it by the old name until P5/P6 rebuild their toolbars, but there is only one implementation of "which period does this indicator have".
- P3: `periodControl` has a fourth, unspecified rendering — `data-mode=snapshot`, a mono `as of …` badge — for an indicator with one published as-of and no year series (the BBR keys, the school keys). v2.6 rendered nothing there; a blank slot says less than the date, and §2.4 wants an as-of on every surface.
- P3: `hz=` is serialised only when the horizon is the period actually on screen (a Climate indicator, the climate sheet, the test property, or the map's `climate=1` overlay while it still exists). That is what "switching family resets `hz`" means for the URL (spec §3.2, §4.3). `HZ.h` itself is left alone in memory, so moving out of Climate and back does not lose the reader's horizon inside one session.
- P3: `climValue(o, k, hz)` and `climHzFor(k, hz)` take an explicit horizon, defaulting to `HZ.h`. A Climate chart reads all three at once; before this there was no way to ask for a horizon other than the pill's.
- P3: a Climate indicator on Charts forces `chartMode() === "clim"` — the mode segments (Auto/Line/Bars/Distribution) are replaced by a static `Horizons` badge. None of them can draw Today · 2070 · 2120 truthfully: a line between three published periods would be an interpolation, and this layer makes none.
- P3: **data defect surfaced, not fixed** — the surge keys' registry `desc` has the default horizon baked into the sentence ("Share of the kommune's dwellings inside the **Today** 100-year storm-surge zone", `data/processed/makro.json`, built from `config/indicators.json`). On a chart that draws all three horizons that sentence is wrong, so `climDescNeutral()` drops the horizon word in that one subtitle. Data task for daytime: make the desc horizon-free in the build.
- P3: Data › Areas keeps sorting **best first** (ascending for `lower_better`), not "descending by value regardless" as AC-D5's parenthetical says. The parenthetical contradicts itself ("sort descending by value regardless; check first two values monotone"), the caption under the table has said "best first (↓ = lower is better)" since v2.6, and every column header carries `data-best`. The AC test checks monotonicity in the direction the header advertises.
- P3: all nine `QUICK_KEYS` chips are rendered, not the "first 8" of §4.2 — the section's own diagram lists nine (Growth · Price/m² · Rent · Unemp. · Rented · Supply · Crime · Outlook 2040 · Surge dwellings) and dropping one would drop the Climate chip.
- P3: the row availability tag has five shapes, not the three named in §4.2: `muni`, `2016–`, `snapshot` plus `horizons` for Climate and the window (`2026→2040`) for Outlook. "snapshot" is wrong for both of those families and the group pill alone does not say which window.
- P3: `tests/ui_smoke.py` gained `our_url()` — it reads the title of whatever answers the `--url` it was given and, when that is not this dashboard, serves the repo's `dist/` on a free loopback port from inside the test process (`tests/ui_ac.py` imports it). A sibling project took :8080 mid-phase and `overnight.sh gate` only starts a server when nothing answers there, so a whole gate went red for a cause outside the repo. The gate's port stays 8080 and `overnight.sh` is untouched — the recovery belongs in the runner, which is the thing that knows what it is supposed to be testing.
- P3: `tests/ui_ac.py`'s `boot()` now hops through `#data/areas/kommune` before returning to the map. `go()` only re-renders when the hash changes, so an AC that ended on `#map?ind=growth` handed the next one its exact DOM — including a popover left open. The hop guarantees a fresh render; the runner's error capture also keeps Playwright's first lines now, because the last line of its traceback is "- waiting 500ms", which names neither the call nor the locator.
- P4: the Outlook family's map ramp needs **two** purple hues, not one. Spec §2.1 asks for "Outlook = purple 5-step", but every Outlook indicator is `scale: diverging` (shrinking vs growing about zero), so a single hue would throw the sign away. `RAMP_GROUP.Outlook` is violet `#5B4A9C` (the spec's `--proj`) for the growing side and plum `#933F73` for the shrinking one: both read as projection against the green observed ramps, and which way the projection goes is still legible. The registry's own `hue`/`hue_neg` are left alone — the override is by group, in `mkShade()`, so Charts and the area page get the same ramp.
- P4: the two halves of the climate overlay (`clim=areas,surge`) become **one** context layer with one switch (`zones=0`). Spec §4.4's Context section lists one row, and now that the layer is bound to the indicator rather than to a button of its own, "draw the extent but not the official risk areas" is a distinction without a reader. `climFilterParse`/`climFilterSerialise` are deleted from `src/climate_core.js` with their tests; a shared link carrying `clim=` still works, it just shows both parts.
- P4: `climOn()` is `CLIM && S.view === "makro" && isClim(MK.ind) && MK.zones`. The `S.view` term is new: the test property and the climate sheet draw their own climate layers and must not be switched by the macro map's indicator.
- P4: the old `infra=1&public=1&services=1` → `lay=infra,public,services` rewrite lives in `route_core.layerFlags()`, not in `parseHash()` — P2's rule that a hash spelling belongs to the alias table. It is idempotent (a link that already names `lay=` keeps it and the flags only add), so `parseHash()` reads one key and `hashFor()` writes one.
- P4: the Layers menu's open state (`UI.layOpen`) survives a re-render but not a navigation. Ticking two layers should not need two trips to the button, and every tick re-renders; but the menu has no business following the reader to another municipality, so `hashchange` closes it.
- P4: the legend stack is bottom-right, wraps into **at most two** columns (spec §4.5 "max 2 cards wide") and then folds. `lgFit()` re-runs after every legend refill and folds the topmost feature legend to its title — services, then public, then infra, then the zones — until the stack is inside the map, inside 60 % of its height and no wider than 460 px. The indicator legend never folds: it is the one that explains the fill. A legend the reader opens by hand is remembered in `LEGO` and never auto-folded again.
- P4: the drilled municipality card (`muniStrip`) became a `<details>`, **closed** by default, with the identity line and the five headline figures in the summary and the projects / public / climate / outlook blocks inside. Spec §5.1 asks for it to be collapsible with the state in `localStorage`; closed by default is what buys the drilled map its place on the first screen at 1366×768 (it was 614 px down, it is 302 px now).
- P4: the unified search matches on the **name and the code only**, never on the " — municipality, Hovedstaden" tail it displays. Matching the whole display string meant a single typed letter brought back half the country for the word "municipality".
- P4: a coordinate in the search offers exactly one action — "Open as test property" (`#property?p=…`), per the phase file. Dropping a pin on the map itself is still reachable (`map?pin=…`, the popup's own action, the test property's "Open on map"), it is just no longer something the search offers, so the box has one answer per kind of input.
- P4 — **limitation surfaced, not fixed**: the Copenhagen quarter registry (`data/processed/cph.json`) has no Climate keys, so `curInds()` swaps a Climate indicator out when the reader drills into `#map/101` in quarter mode — and the zones go with it. That is v2.6 behaviour, and the fix is a data one (quarter-level climate figures). `AC-LG1` uses Aarhus for this reason. Daytime data task.
- P5: the study row is a component, `studyRow(entity, opts)` → `chartPanel(e, opts)` + `miniMap(opts)`, and it reads nothing off `AR` or the hash. The phase file asks for it so P6 can point it at the finest area a test-property pin sits in; keeping the entity and the four ids (`mapId`, `legendId`, `mapKey`, `note`) in `opts` is what makes that a call rather than a copy.
- P5: choosing an indicator on the area page does **not** go through `render()`. `pickInd()`, `climSetHz()` and the year select all call `areaRefresh()` first, which replaces `#artop`, the chart panel and `#arsecs` and repaints the map's polygons through `arMapPaint()` on the map that is already there. AC-P4 asks for the scroll position; the full-screen overlay and the reader's own pan and zoom fall out of the same rule. `areaRefresh()` returns false anywhere else, so every call site still ends in `renderKeep()`.
- P5: `arMapInit()` was split into "build the map" and `arMapPaint(fit)` "draw this indicator on it". Only the init fits the bounds; a repaint never moves the camera — the same rule as "zooming never changes the selection" read from the other end: changing the indicator must not move the map either.
- P5: the four toggles are one URL key, `show=`, with `none` as the spelling for "the reader closed the one that opens itself". Writing every open section always would put `show=outlook` on the default link of every municipality page, which is noise on the link a reader shares.
- P5: the v2.6 area keys `t=` and `g=` are translated in `route_core.areaTabs()`, not in `parseHash()` — P2's rule that a hash spelling belongs to the alias table. `t=bbr` and `t=ind` both become `show=figures` (the BBR distributions moved inside All figures), `t=sub` becomes `show=sub`, and `g=` is dropped: it named a tile group of a block that no longer exists.
- P5: the BBR housing-stock distributions became a sub-heading inside **All figures** rather than a fifth toggle. Spec §5.2 lists four toggles and does not say where the old BBR tab went; a section of its own would have made five, and the distributions are figures about this area like the rest of that table.
- P5: the Safety survey and the KK-vs-DST forecast note are sub-headings of All figures on a quarter page (spec §5.2), and the forecast caveat also stays inside the Population outlook card — it is that chart's own caveat, and a reader who opens the chart and not the table must still see it.
- P5: the mini map's full-screen overlay is `z-index:1400`, not the spec's §4.6 `100`. The IndicatorPicker has been `z-index:1200` since P3, so at 100 the picker button floats over the full-screen map.
- P5: the full-screen overlay carries its own chips row (`data-testid=minimap-chips`), because it covers the page's toolbar and the phase file requires choosing an indicator to work while the map is full screen. It is a second chips row on the page, so it deliberately does not answer to `ind-chips` — AC-I4 asserts exactly one filled chip under that id.
- P5: the header's `Show on map` / `↗ Chart` / `Buildings ›` stay in the header card, where spec §5.2 draws them, rather than moving to the top bar's actions slot that P4 introduced for the map's Full screen. They are about this area, not about this page.
- P5: the distribution strip's viewBox is 640 units wide, not the 900 the other charts use. A 900-unit box scaled into a ~640 px panel shrinks every label to 70 %, below the 11 px the contrast rule in §7 allows.
- P5: the Climate bars label the axis with the horizon only; the Klimaatlas period each one covers is one caption line under the chart. Side by side on the axis the three periods overwrite each other at every width.
- P5: a Climate bar is drawn only where the publisher has a figure — a missing horizon is a `–` on the axis, never a zero-height bar. AC-P3 counts three bars on `#area/kommune/101`, where all three are published.
- P5: **AC-P5 is asserted on the study row, not on the page.** Horizontal overflow at 390 px is the v2.6 shell defect (`--sidew:100%` in the ≤900 px media query) that P8 owns and that `OVERFLOW_FATAL` still reports as a note; the row and its two halves are checked against the column they sit in instead. A Leaflet container always reports `scrollWidth > clientWidth` because it paints tiles past its own edges, so the map is judged on the wrapper that clips them.
- P5: the KK vs BBR "built 2010+" gap (ENG_BRIEF §3.4) is surfaced, not fixed: on the four Copenhagen quarters where the two shares differ by more than 15 pp (Holmen og Refshaleøen, Vesterbro syd, Nordøstamager, Faste Batteri) the two rows are renamed to name their definition and a one-line caveat says why they disagree. Labels only — `data/processed` is untouched. Daytime data task: `max(byg026, byg027)` or the unit-level commissioning field in `build_bbr.py`.
- P5: the area page's history line gained a fourth series on municipality pages — Denmark's own published figure from `D.national`, dashed, beside the median of the 99. The two are different things (a national statistic vs the middle municipality) and the legend names both.
- P5: a quarter's mini map stops at zoom 12, not 13. A kvarter is small enough that maxZoom 13 leaves one neighbour on screen, and §4.6 asks the mini map to show the area among its peers.
- P5: `ePeers(e, key)` names the pool a figure belongs to — the page's own level, or the municipalities when the value on screen is the municipality's — and the tiles, the panel headline, the history chart's median line and the distribution strip all use it. Before this an inherited figure was compared against the median of 606 postal codes that do not publish it, which came out as `–` rather than as a wrong number, but it also meant a municipal figure read on a postal-code page had no comparison at all. The rank is still withheld for an inherited figure: §4.7 says the tile reads "municipality figure" *instead of* a rank, because the rank would be the municipality's and the page is not about the municipality.
- P5: `tests/ui_ac.py`'s `goto(..., wait=…)` waits for `state="attached"`, the way `tests/ui_smoke.py` has since P1. A Leaflet pane has no size of its own, so the default "visible" wait spent its full 15 s on every map AC and then passed regardless — about 90 s of every run.
- P6: the test property is the **same** `studyRow(entity, opts)` the area page is built around, pointed at `tpEntity()` — the pin's finest published area (quarter > postal code > municipality). The level is named as a `read as <level>` tag in the identity line, so nobody reads a quarter's figure as the address's own.
- P6: `curInds()`, `curPool()` and `pickLevel()` now branch on `S.view === "analysis"` and answer from that entity. Before this the test property inherited the **map's** context (`cphMode()`), so a reader who had drilled into Copenhagen got the quarter registry on a pin in Aarhus. The consequence: a Copenhagen pin no longer offers the national-only indicators (price/m², private rent) in its picker — the quarter layer does not publish them, and the profile table never listed them either.
- P6: the radius is a select in the toolbar (`rad=`, 500 m · 1 km · 2 km · 5 km, default 1 km) and it drives **both** the solid ring on the mini map and the ring the "Public buildings within" and "Schools within" sections count inside. `AN_RING_M` (1 000 m) stays as the default, so an old link is unchanged. `TP.rad` — the *map's* overlay distance filter — is a different thing and is untouched.
- P6: `Layers ▾` is one component with two lists. `MAP_LAYERS` is the map's (`infra,public,services` + zones + the pin radius), `TP_LAYERS` the test property's (`infra,public,buildings` + the storm-surge zones of its municipality); `mapLayerToggle()` routes to `tpLayerToggle()` while the test property is on screen. The two `lay=` keys mean different things, which is why they are two lists and not a flag on one. The v2.6 `data-anlay` pill bar is deleted.
- P6: the mini map's legends are one `.maplegs` stack — indicator legend first, the pin's overlay legends under it — in the same order and under the same auto-fold rule as the macro map. `lgFit()` was split into `lgFitIn(wrap, map, order)` and now runs over both stacks, so §4.5's "never more than 60 % of the map's height" holds on the mini map too.
- P6: **AC-P1MM (P1-local) was updated, not weakened.** It counted "3 rings + the pin" on `LF.anPinG`; §5.5′ adds the ring the radius select names, so it counts 5. The invariant it exists for — the pin and its rings survive the overlays that used to throw before them — is unchanged.
- P6: a link pasted into the box replaces the pin **and its label**. A different address is a different property, so it does not inherit the previous one's name; AC-TP5 asserts the hash carries exactly one item.
- P6: `#property?p=a;b` — the codec in `route_core.js` stays list-capable and `propParse()` still returns every item, but the view renders only the first and `hashFor()` writes only one (amendment A2). Several pins on one map is the owner's later idea and will need no format change when it lands.
- P6: identical rows in "Public buildings within the ring" are folded into one row with a `×n` count when the name, the BBR use code and the distance (to 20 m) all match — one building registered as several bodies. Nothing is dropped: the caption says how many records were folded, and the distance shown is the nearest of them.
- P6: the eight sections are `tp-sec-<name>` with their own `AN.show` set and their own `data-tpsec` branch, beside the area page's `AR.show` / `data-sec`. One shared set would have made a section opened on the area page open a different section here; the URL key is the same `show=` because it means the same thing on both pages.
